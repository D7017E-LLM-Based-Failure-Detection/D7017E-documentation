Division of Responsibilities

Subsystems & Working Groups

Three groups collaborate to build one cohesive cyber-physical system and author one unified final report.

Group 1

Testbed, Telemetry & tinyML

Group Docs ↗

Operates the physical conveyor belt in the lab, instruments it with sensors (vibration, optical, current), establishes a robust telemetry pipeline, and implements tinyML models running directly on microcontrollers. G1 represents the interface to the physical process for the entire system.

Core Competencies: IEC 61499 distributed automation (EAE), microcontroller programming, edge feature extraction, sensor calibration, real-time safety interlocks.
Deliverables: Sensor telemetry stream · On-device model binaries · Physical hardware map Filter G1 Logs →
Group 2

LLM ↔ Knowledge Graph Reasoning

Group Docs ↗

Models the automation equipment, physical topology, sensor bounds, and failure taxonomy using RDF, OWL, and SHACL ontologies. Builds an explainable diagnostic loop combining structured graph validation with LLMs to interpret anomalous events into human-understandable root-cause analyses.

Core Competencies: Semantic Web standards (RDF, OWL 2, SHACL, SPARQL), LLM prompt orchestration, neuro-symbolic reasoning, explainable AI (XAI).
Deliverables: System ontology (`.ttl`) · Reasoning service · Explainability benchmark Filter G2 Logs →
Group 3

iCAP Platform & Web UI

Group Docs ↗

Develops and maintains the SCADA-like operational platform. Provides high-throughput time-series storage, responsive web visualization dashboards, alarm handling, and service orchestration for the knowledge graph and edge ML pipelines.

Core Competencies: SCADA architecture, time-series databases, web visualization (React/Vue/Dash), MQTT brokers, Docker orchestration.
Deliverables: iCAP SCADA dashboard · Ingestion broker · Time-series API Filter G3 Logs →
